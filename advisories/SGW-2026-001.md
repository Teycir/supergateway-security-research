# SGW-2026-001 — Unauthenticated remote DoS in stdio→SSE mode

## Summary

In stdio→SSE mode, `POST /message?sessionId=<key>` looks up the session in a plain object. Any key inherited from `Object.prototype` (`toString`, `constructor`, `__proto__`, `hasOwnProperty`, `valueOf`, …) returns a truthy value that is not a session. The handler then dereferences `session.transport`, throws a `TypeError` inside an `async` Express handler, and Node.js terminates on the unhandled rejection. A single unauthenticated request kills the process and every attached MCP session.

## Affected component

- `src/gateways/stdioToSse.ts:125` — `const sessions: SseSessions = {}`
- `src/gateways/stdioToSse.ts:222–239` — unguarded lookup and `await session.transport.handlePostMessage(...)` in an `async` route

## Impact

- Remote, unauthenticated, single-request denial of service against any default deployment (`supergateway --stdio ... --port ...`).
- All sessions and spawned MCP children die with the process (availability loss, not just one session).
- No session needs to exist, and no credentials are required; `--apiKey` does stop the attack because the key check runs first.

## Root cause

```ts
const sessions: SseSessions = {}            // plain object, inherits Object.prototype
...
const sessionId = req.query.sessionId as string
...
const session = sessions[sessionId]         // "toString" -> Function, "constructor" -> Object, ...
if (session) {
  logger.info(...)
  await session.transport.handlePostMessage(req, res)   // TypeError: undefined 'handlePostMessage'
}
```

`catch`-free `async` route handlers in Express 4 reject into an unhandled promise rejection; Node.js 15+ exits by default.

## Reproduction

```bash
./scripts/bootstrap.sh                       # vulnerable build in .work/
./pocs/rt01_harness.sh toString              # deterministic single run
# or against any running instance:
./pocs/rt01_exploit.sh http://127.0.0.1:8000
```

Observed: `curl` code `000`, port closed within 2 s, health `000`, and in the gateway log:

```
TypeError: Cannot read properties of undefined (reading 'handlePostMessage')
    at .../dist/gateways/stdioToSse.js:135
```

Full sweep: 5 payloads × 3 rounds = 15/15 crashes, plus one crash over a non-loopback address, plus a `curl`-free raw TCP reproduction. See `evidence/` and `docs/verification.md`.

## Fix

`patches/rt01-map-sessions.patch` replaces the plain object with a `Map`, validates ownership explicitly, and rejects unknown sessions with `503`. Validated: all five payloads return `503`, the process stays alive, health is `200`, and a legitimate SSE session still completes `tools/call` returning the canary.

Minimal alternative for maintainers: `const sessions = Object.create(null)` plus a `hasOwnProperty`/`Map` check. The full patch is preferred because it also fixes related session bookkeeping.

## Workarounds

1. Require `SUPERGATEWAY_API_KEY` (verified: unauthenticated malicious POST → `401`, process alive).
2. Bind to loopback (`--port` with a loopback-only proxy) and do not expose the SSE port.
3. Prefer stdio→Streamable HTTP (stateful), which uses a `Map` and is not affected (verified: `mcp-session-id: toString` → `404`, alive).
